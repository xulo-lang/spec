# Macro Context

A macro reads the surrounding program through six read-only operations. The
compiler implements each source-level `ast` function as one context operation.
The context is the **pre-expansion** environment: a lookup sees what was written
before any macro expanded, which is what makes expansion order predictable
([expressions/calls.md](../expressions/calls.md)). The macro's own input
record is different: it is the declaration or expression at the point in the
expansion order where this macro runs
([type-system/checking-rules.md](../type-system/checking-rules.md)).

## Read-only rule

The context operations never mutate a declaration, a type, a function, or a
module. They return copies or read-only views. A macro that wants to change
the program returns an AST fragment; the compiler inserts it. A macro cannot
add a name to the context, cannot change a signature, and cannot make a later
macro argument resolve.

## The six operations

| Instruction | Source API | Result |
|-------------|------------|--------|
| `LookupType` | `ast::lookup_type(name: string): ast::TypeInfo?` | the type's `ast::TypeInfo`, or `null` |
| `LookupFunction` | `ast::lookup_function(name: string): string?` | the function's signature in source form, or `null` |
| `LookupVariable` | `ast::lookup_variable(name: string): string?` | the variable's type in source form, or `null` |
| `FieldsOf` | `ast::fields_of(name: string): List<ast::FieldInfo>` | the fields of a struct or enum, or an empty list |
| `CurrentSpan` | `ast::current_span(): ast::Span` | the macro invocation's span |
| `SpanOf` | `ast::span_of(node: ast::AstNode): ast::Span` | the node's own span |

`name` is looked up by the ordinary resolution order of
[names.md](../names.md): local bindings first, then the module, then imports,
then the prelude. A name that does not resolve returns `null` (or an empty
list for `FieldsOf`); the macro decides whether that is an error and returns
an `ast::MacroFailure` (`E1008`).

`ast::TypeInfo` describes `struct` and `enum` declarations. `ast::lookup_type`
returns `null` for a trait, an alias, or a primitive type, and `fields_of`
returns an empty list for them; a macro that needs the generic parameters of
such a declaration inspects its own input record instead.

`ast::current_span()` is the span of the attribute argument, derive target,
or function macro call that caused the current expansion. `ast::span_of(node)`
is the node's own span; for a node produced by `ast::quote!`, it is the quote
call site unless the node came from a hole with a span.

The context is read-only and pre-expansion, so a lookup does not see:

- a declaration generated by an earlier macro;
- a name generated by the macro currently running;
- a macro-local binding of the program being compiled.

The implementation MAY cache the context between macro calls; a cache hit and
a miss MUST return the same result. An expansion cache records the context
queries and answers the expansion observed; they are part of its key
([cache.md](cache.md)).

## Additional `ast` functions

Two node helpers are not context operations but are part of the same surface:

```typescript
fn ast::node(kind: string, fields: Map<string, ast::Value>): ast::AstNode
fn ast::field(node: ast::AstNode, name: string): ast::Value?
```

`ast::node` constructs a node from a kind and a field map. `ast::field` reads
one field of a node; an absent field is `null`. A macro normally uses
`ast::quote!` for anything larger than a single node.

```typescript
fn ast::call_derive(name: string, input: ast::DeriveInput | ast::Value)
    : Result<ast::DeriveOutput, ast::MacroFailure>
fn ast::call_attribute(name: string, input: ast::AttributeInput | ast::Value)
    : Result<ast::AttributeOutput, ast::MacroFailure>
fn ast::call_function(name: string, input: ast::FunctionInput | ast::Value)
    : Result<ast::FunctionOutput, ast::MacroFailure>
```

The three call entry points invoke another macro from a macro body. Each takes
the input record matching its own kind, or an `ast::Value` target node, and
returns the matching output record. A target of another kind is `E1006`; a
value that cannot be converted to the input record is `E1002`. They follow
the macro-call rules in [execution.md](execution.md). They are meaningful
only during compile-time execution: when the same functions are
called at runtime, the macro registry does not exist and the call panics as an
ordinary runtime failure. A macro that uses a call entry point is covered by
expansion tests and integration tests, not by direct runtime unit tests
([testing.md](../testing.md)).

## Diagnostics

A context lookup that returns `null` is not itself a diagnostic. The macro
author decides whether the absence is acceptable and, if not, returns
`Result::Err(ast::MacroFailure { message: message, span: span })`; the compiler reports `E1008`
with the author's message and span
([errors.md](errors.md), [builtins/errors.md](errors.md)).
